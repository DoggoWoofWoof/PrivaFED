# Privacy Design & Threat Model

This document outlines the theoretical framework and adversarial model used to evaluate the Priva-Fed retrieval system.

## 1. Privacy Design Principles

Priva-Fed employs a defense-in-depth strategy, combining traditional cryptographic protection with noise-based semantic obfuscation.

### VS-ADP (Vector-Space Approximate Differential Privacy)
- **Mechanism**: Dimensionality-aware Gaussian noise is added to query embeddings prior to broadcast.
- **Calibration**: Per-dimension $\sigma = \text{noise\_scale} / \sqrt{d}$. This ensures the noise-to-signal ratio (NSR) remains constant regardless of the embedding model's dimensionality ($d=384$ for `all-MiniLM-L6-v2`).
- **Accounting**: Uses Rényi Differential Privacy (RDP) for tight composition. At high noise levels ($ns=2.0$), framing shift to "empirical adaptive resistance" due to high $\epsilon$ accumulation.

### HE-Lite (Homomorphic Encryption)
- **Mechanism**: CKKS homomorphic encryption (via TenSEAL) is used to protect relevance scores in transit and during aggregation.
- **Goal**: Blocks an adversary (including an honest-but-curious Hub) from observing the raw similarity values generated by local nodes.

### LSH (Locality Sensitive Hashing)
- **Mechanism**: Maps dense continuous embeddings into 64-bit binary signatures using SimHash.
- **Goal**: Provides a lightweight, non-cryptographic baseline alternative for score protection by allowing matching via Hamming distance rather than exposing exact continuous dot-products.

### Secure Aggregation (P2P Masking)
- **Mechanism**: Zero-sum pairwise masks are applied to scores. 
- **Goal**: Ensures the Hub only sees the global sum of scores across the federation, preventing the identification of which organization contributed which result.
- **Note**: Pass 1 candidate identifiers (document IDs nominated by each node) remain visible to the Hub prior to the masking phase. This is a known limitation documented in the threat model.

## 2. Threat Model

We define two primary categories of adversaries based on the interface they intercept.

### Category A: Query-Vector Interception
**Attacker Goal**: Reconstruct the user's natural language query or identify the specific entity being searched for.
- **Attackers**: Eavesdroppers on the Hub-to-Node communication channel.
- **Defense**: VS-ADP noise and K-Anonymity (chaff queries).
- **Metric**: Attack Success Rate (ASR).

### Category B: Score and Transit Interception
**Attacker Goal**: Map document relevance profiles or reconstruct document embeddings.
- **Attackers**: Honest-but-curious Hub orchestrator or transit-layer eavesdroppers.
- **Defense**: HE-Lite score encryption and P2P Masking.
- **Metrics**: Membership Inference (MIA), Score Inference (ScoreInf), Embedding Reconstruction (Recon).

---

## 3. Privacy-Utility Paradox
The empirical evaluation reveals that cryptographic protection (HE) comes with a significant **bandwidth cost (~2,964x overhead)**. Conversely, noise-based protection (VS-ADP) is cheap but requires careful calibration to avoid significant **utility loss**. The **Combined Pipeline** is the recommended operating point for score-side confidentiality, but adaptive query averaging still requires operational controls (rate limiting/chaff) to sustain query-side resistance.
